# 社員画面の操作と検証

[開発版の案内](../README.md) · コマンドの実行場所は `hermes-ai-hub/` です。

## 自分の議事録から更新商談メモを仕上げる

1. 社員のホームで「更新商談の準備」を選び、「自分の資料を使う」を開いて議事録を貼り付けます（6,000文字まで）。契約書は添付せずに案件の契約台帳を使えます。添付する場合は、文字を選択できるPDF・DOCX・UTF-8のTXT/MDに対応し、5 MB・抽出本文12,000文字までです。「今回使う資料を確認」で、依頼に渡す2資料の本文を送信前に確認できます。「手順を探す」からも同じ入力欄を開けます。議事録が空欄なら既存の合成議事録を使います。
2. 更新商談の準備を依頼し、Hermes の確認に回答します。メモの [1] から契約台帳、[2] から依頼時の議事録を開けます。
3. 同じ仕事の「修正内容」に「上司向けに3行にして」などと入力し、「修正を依頼する」を選びます。本人用の Hermes に、元の資料、回答、直前のメモと修正指示を渡します。修正版が完成すると「表示する版」で初稿と修正版を切り替えられます。
4. 本文の出典番号から原文を開きます。一意に対応した文や日付を強調し、「資料を並べて比較」で両方の原文を確認できます。同じ仕事で追加質問をすると、回答はメモと別に残ります。「表示する版」「第1版と見比べる」「この版を採用」で採用版を選べます。
5. 「出典付きでコピー」は表示中の本文と出典一覧をコピーします。「Markdownで保存」は同じ版をファイルに書き出します。

ローカル環境では合成資料を使用します。オフラインの合成モデルは3行要約や箇条書きなどの形式を再現します。自然文による改訂の検証には、Hermes に接続したローカル実モデルを使用できます。ブラウザーでの一連の確認は `node test/browser/employee/memo-workflow-browser.mjs`、比較環境では末尾に `--compare` を付けて実行します。

[議事録の貼り付けから修正版のコピーまでの画面・実行記録](../evidence/renewal-employee-workflow.md)

## 一般ユーザーの仕事・共有・定期実行

ホームの初期設定は「Hermesにおまかせ」です。「自分の資料を使う」にファイルを添付するか原文を貼り、依頼内容を書いて送信します。本人用Hermesが依頼に合う手順書を開き、MCPツールを選んで実行します。初稿の根拠欄には、選んだ手順名と使用したツールも残ります。ツールが使う資料は依頼時に保存した原文です。初稿で次の根拠を開けます。

依頼文に `@` と資料名を入力すると、閲覧できる資料を上下の矢印キーと Enter で選択し、Escape で候補を閉じられます。指定した資料は送信前に「原文を開く」で確認できます。

| 依頼例 | 元の仕事で確認できること |
| --- | --- |
| このCSVから返品を除き、商品別に売上を合計して | 「集計条件と元の行」に、金額列、グループ列、絞り込み条件、採用・除外した行番号と原文を表示します。UTF-8の見出し付きCSVに対応します。 |
| 出張を取り消したとき、精算に何が必要？ | 「社内の資料置き場を選ぶ」で「社内規程」と「申請案内」を選ぶと、ファイルを添付せずに両方を検索できます。本文の出典番号から、検索時の版の条項を開けます。 |
| この制度変更を社員向けに案内して | 「案内に使った原文」で、対象者、開始日、必要な行動を確認できます。資料にない項目は「記載なし」と表示します。 |
| 2社の見積を購買向けに比較して | 「参考資料を添付」で2件を同時に選びます。初稿の比較表で各セルの出典番号から原文を開けます。相手の見積に記載がない条件は「要確認（記載なし）」です。「比較表をCSVで保存」で、表示した値・資料名・出典番号を保存できます。 |
| 次回から結論を先に書いて | 「Hermesにおまかせ」で希望だけを送ると、本人用Hermesがプロフィールに保存します。次の依頼では、希望を入力し直さずに回答を受け取れます。 |

見積比較は、専用比較環境で `node test/browser/employee/quote-comparison-browser.mjs` を実行すると、下書きの再開から原文の表示、CSVのダウンロードと読み戻しまで検証できます。[実モデルの見積比較表](../evidence/quote-comparison.png)

見積比較を修正したら、修正版の「この版を採用して個人スキルに保存」で、本人用Hermesが比較項目・順序と判断ルールを `SKILL.md` に保存します。「新しい見積2件で使う」から比較基準を確認し、今回のファイルを2件選ぶと、比較表の各セルから今回の原文を開けます。保存したスキルは「自分用の手順」にも表示されます。

専用の比較環境で `node test/browser/employee/general-assistant-browser.mjs` を実行すると、同じ依頼画面から3件を作り、再読み込み後の成果物・根拠と、別の社員からのアクセス制限を確認できます。

### 成果物から担当窓口に問い合わせる

元の仕事で成果物の版を選び、「問い合わせの起票案を作る」を押します。本人用Hermesがその版から件名・本文・添付候補を準備します。「起票案を確認」で担当窓口を選び、文章と添付を編集してください。「登録内容を確認」では、添付する資料の本文も開けます。「この内容で起票」を押すと、窓口の担当者の「業務スペース」の「承認・登録」に受付票が届きます。

起票案の編集画面にスクリーンショットを1枚貼り付けるか、画像を選択できます。プレビューで表示を確認し、必要に応じて取り除くか差し替えてください。PNG・JPEG、4 MB以下、縦・横ともに4096ピクセル以下の画像を使えます。「画像から下書きを作る」を押すと、利用が許可された画像対応のローカルモデルが表示を読み取ります。「画像から読み取った表示」を確認・修正し、操作の経緯は「ご自身が行った操作」に記入してください。窓口には確認して起票した文章が届きます。読み取りを使えないときは、本文に画面の表示を入力してください。

受付票は成果物の版ごとに1件です。依頼者は元の仕事から、担当者は「窓口で受け付けた問い合わせ」から、同じ受付番号を開けます。担当者には依頼者名と受付時刻、確認した件名・本文・選択した資料のテキストが表示されます。元の仕事とやり取りは依頼者の画面で管理します。[担当者の受付画面](../evidence/inquiry-receipt.png)

担当者は受付票の「受付票に回答」から回答を1件送れます。依頼者が「通知」で受付番号と件名を確認して開くと、元の仕事の起票時の版に移動し、回答本文・担当者名・回答日時が表示されます。回答は受付票からも読み返せます。[窓口の回答済み受付票](../evidence/inquiry-desk-answer.png)・[元の仕事の回答欄](../evidence/inquiry-answer.png)

回答欄の「この回答を反映するようHermesに依頼」を押すと、本人用Hermesが起票時の版をもとに修正版を作ります。本文の出典番号と受付番号のリンクで窓口の原文を開けます。起票時の版と見比べて「この版を採用」を押すまで、それまでの採用版を保持します。

窓口の回答について確認したいときは、元の仕事の「同じ受付票に追加質問」から送信できます。回答を反映した版からは、参照資料の「やり取り・追加質問」で元の回答欄を開けます。窓口担当者の「業務スペース」の「承認・登録」には「追加質問あり」と表示されます。担当者が同じ受付票から再回答すると、依頼者の通知からその回の再回答を直接開けます。最初の問い合わせから各回の質問・回答までを時系列で読み返せ、再回答後は次の質問を送れます。

[依頼者が通知から開いたやり取りの画面](../evidence/inquiry-followup-history.png)

再回答を成果物に反映するときは、元の仕事の履歴から使いたい回の「この再回答を第○版に反映するようHermesに依頼」を押します。本人用Hermesが現在の採用版をもとに修正版を作ります。修正版の出典リンクには受付番号と回答回が表示され、その回の追加質問と再回答を開けます。受付票から修正版に戻り、「現在の採用版と見比べる」で内容を確認して「この版を採用」を押します。

[採用版と修正版の比較画面](../evidence/inquiry-round-comparison.png)・[出典で開いた追加質問と再回答](../evidence/inquiry-round-source.png)

再回答を反映した版を採用すると、依頼者は元の仕事の「受付票 #○ を解決済みにする」で問い合わせを終了できます。依頼者の仕事と担当窓口の受付票には、解決した人・日時・そのときの採用版と回答回が残ります。解決後も同じ受付票で最初の質問から再回答までを読み返せます。

[依頼者の解決履歴](../evidence/inquiry-resolved-requester.png)・[担当窓口の解決済み受付票](../evidence/inquiry-resolved-desk.png)

登録先はHub内の受付です。初期設定の窓口と担当者は [inquiry-desks.json](../src/inquiries/inquiry-desks.json) にあります。運用時は同じ形式のJSONファイルを `AI_HUB_INQUIRY_DESKS` に指定し、Hubコンテナを再作成してください。指定した所属かつ有効な担当者のいる窓口が社員画面に表示されます。専用比較環境で `node test/browser/inquiries/inquiry-browser.mjs` を実行すると、依頼者と担当者の両画面で確認できます。

### 売上集計を自分用の手順に保存する

完了した集計の「集計条件を自分用に保存」で、金額列、グループ列、採用・除外する値と出力列を確認して名前を付けます。「手順を探す」→「自分用の手順」で手順名を開き、今回のCSVを選んで実行します。保存されるのは集計条件です。各回の入力と合計、採用・除外した行はその回の仕事に残ります。列の並び順を変えたCSVも使えます。必要な列が欠けている場合は受付前に列名を表示します。

今すぐ、日時指定の1回、毎週・毎月の実行に対応します。定期実行は「次回分を確認」で、その回に使うCSVを登録します。未登録の回はスキップします。専用比較環境で `node test/browser/employee/csv-skill-browser.mjs` を実行すると、初回の集計から翌月分の集計まで社員画面で確認できます。`--schedule` を付けると月次予約の次回分も検証します。[翌月CSVの集計と元の行](../evidence/personal-csv-skill.png)

### 社内の資料置き場を登録する

Compose は既定で `library-data` のサンプル規程と申請案内を読み取り専用で Hub にマウントします。実資料を使うには、`AI_HUB_LIBRARY_DIR` にホスト上のルートを指定し、以下の構成でファイルを置いてください。

| ルートからの位置 | 選択できる社員 |
| --- | --- |
| `shared/<置き場名>/` | 全社員 |
| `teams/<所属名>/<置き場名>/` | その所属の社員 |
| `users/<社員ID>/<置き場名>/` | 本人 |

各置き場の直下にある UTF-8 の TXT・MD、文字を抽出できる PDF・DOCX が対象です。1ファイルは5 MiB・抽出後65,536文字まで、1依頼の検索範囲は12か所・合計16 MiBまでです。社員は送信前に検索範囲を確認できます。Hermes が見つけた資料の本文と版を仕事に保存し、引用した箇所を強調します。専用比較環境の `node test/browser/employee/library-search-browser.mjs` で、横断検索、範囲の限定、該当なしの表示を確認できます。

| 入口 | 操作 |
| --- | --- |
| ホーム → 依頼する | 「依頼の種類」で「会議の整理」「週報の下書き」「自由に依頼」を選び、例文を自分の言葉で書き換えます。「自分の資料を使う」に会議の記録や週の進捗記録を貼り付け、「今回使う資料を確認」して依頼します。社員本人の Hermes が成果物を作り、本文の出典番号から依頼時の原文を開けます。 |
| 通知 | 確認待ち・完成・追加質問への回答が届き、クリックすると該当の仕事に移動します。ブラウザー通知を許可すると、AI Hub を別タブで開いている間も通知します。 |
| 依頼一覧 | 顧客名・依頼内容・資料名・原文・過去の版を含む成果物で検索できます。「新しい依頼に使う」で指示と出力形式を引き継ぎ、新しい資料を選んで依頼します。受付済みの初回依頼は、Hermes が着手する前なら取り消せます。 |
| 手順を探す | 「自分用の手順」に名前・依頼内容・出力形式を保存し、自分だけで繰り返し使えます。 |
| 成果物の「同僚に共有」 | 版・本文・宛先を確認して共有します。相手にはその時点の本文を保存したコピーが届き、「業務スペース」の「案件・引き継ぎ」から開けます。 |
| 依頼一覧 → 予約 | 曜日・時刻（日本時間）を決めると、自分が直近7日間に完了した仕事をもとに本人用の Hermes が週報を作成します。下書きは「依頼一覧」に入り、完了通知が届きます。一時停止・再開と前回の下書きの確認ができます。 |

週報は Hub の稼働中に受け付けます。再起動時に期限を過ぎていた場合は直近の予定枠を1回だけ処理します。資料には同じ所属で参照できる直近40件、合計6,000文字までを使います。定期実行が作った週報は集計から除きます。添付の本文抽出に使う Poppler と Python は Hub のコンテナに含まれます。

## 日々の仕事と予約

週報の採用版から「この版から定期下書きを予約」を選べます。自分用に保存した手順の場合は「手順を探す」の手順詳細から「定期実行を設定」を選びます。使う資料、繰り返し、次回日時（日本時間）、保存先を確認してから登録します。予定時刻に本人の「依頼一覧」へ「定期下書き」が入り、内容と出典を開いて修正を依頼できます。共有や社外への送信は予約から行いません。「依頼一覧 → 予約」で一時停止や再開ができ、元の資料の利用資格を失った予約は停止します。CSV手順では、実行回ごとに「次回分を確認」から新しいCSVを登録します。個人の見積比較スキルでは、その回の新しい見積書2件を同じ画面から登録します。

| やりたいこと | 社員画面での操作 |
| --- | --- |
| 指定日時に一度だけ依頼する | いつもの依頼画面で「実行のタイミング」を変更し、日本時間の日時を指定します。「依頼一覧」で予約日時・依頼文・資料を確認でき、着手前は日時の変更と取り消しができます。Hub停止中に時刻を過ぎた予約は、再起動後に同じ依頼IDで受付済みになります。 |
| 資料がそろうまで保存する | 「下書きを保存」で入力中の依頼と添付の抽出本文を保存します。「依頼一覧」→「依頼の下書き」で続きを開き、依頼を確定すると一覧から下書きが消えます。 |
| 後から届く見積を待って比較する | 「Hermesにおまかせ」で「実行のタイミング」を「後から届く見積で比較」に変更します。先に届いた見積1件と比較条件、到着先・ファイル名・日本時間の期限を指定します。「依頼一覧」から元の依頼を開けます。見積が届くと同じ依頼に比較表と両方の出典が表示されます。期限を過ぎたときは本人の通知から元の依頼を開けます。 |
| 今日対応する仕事を確認する | ホームの「今日の仕事」に、回答待ち・今日の実行予約・未確認の成果物が並びます。各行から元の仕事を開けます。 |
| 複数の成果物からまとめを作る | 「依頼一覧」→「複数の仕事から依頼」で、自分の成果物を最大12件選びます。表示された版を資料として保存します。まとめの出典から、その版の本文と元の仕事を開けます。 |
| 会議の宿題を追う | 会議の成果物の「宿題を登録」でメモの一行を選び、担当・期限を保存します。「依頼一覧」→「会議の宿題」で完了を記録し、元の会議メモに戻れます。 |
| 変更箇所を確認する | ホームの「新旧資料を比較」で旧版と新版を貼り付けるか、各ファイルを読み込みます。Hermesが変更点を出典付きで整理し、出典番号を押すと両方の原文を比較できます。 |
| 確認待ちの質問を再通知する | 元の仕事の「あとで通知」で日本時間の日時を指定します。その時点でまだ回答待ちなら通知が届き、元の質問を直接開けます。 |
| 個人手順を繰り返す | 「手順を探す」の各個人手順から毎週・毎月・月末の予定を登録できます。直近7日または30日の完了した仕事を用途で絞れます。短い月で指定日が存在しない場合は月末に実行します。従来の週報と同様、Hubの再起動時は直近の予定枠を1回処理します。 |

2026年11月22日のChrome検証では、単発予約の日時変更とHub再起動を経て週報が完成し、Hermes側の受付記録は実行した週報が1件、取り消した予約が0件でした。ローカル実モデル `qwen3.8-flash-next` でも、納品日・月額・担当者の変更と、会議メモを含む2件の成果物からの出典付き要約を確認しました。[旧版と新版の該当箇所を開いた画面](../evidence/daily-work-comparison.png)

社員画面を再検証する場合は、専用の Compose プロジェクト `ai-hub-daily-work` を `compose.yaml` と `infra/compose.compare.yaml` で起動し、`node test/browser/employee/reservation-browser.mjs`、`node test/browser/employee/daily-work-browser.mjs` を順に実行します。前者は専用Hubの再起動とHermes受付記録、後者は下書きから成果物・再通知・月次実行までを確認します。

到着先には、Hub の資料置き場にある本人が参照できるフォルダを使います。開発環境では `LIBRARY_ROOT` 配下の `shared/<フォルダ>`、`teams/<部門>/<フォルダ>`、`users/<社員ID>/<フォルダ>` が対象です。待機を登録した後、取り込み側で UTF-8 のテキスト、Markdown、PDF または Word の完成ファイルを指定名に移動します。Hub は再起動後もその場所を確認し、比較の着手前に所属とファイルの版を再確認します。

| 宿題をまとめて登録する | 会議メモの「宿題候補を抽出」を選ぶと、本人用のHermesが選択版から候補を抽出します。「宿題候補を確認」で原文・担当・期限を読み、必要な行にチェックして登録します。原文に期限や年の記載が足りない場合は、日付を補うか未定のまま保存できます。同じ版の候補を開き直す際は保存済みの結果を使います。 |
| 案件でまとめる | 各仕事の「案件に整理」で個人の案件を作るか既存案件に追加します。「業務スペース」の案件から、直近の決定事項、未完了の宿題、資料の原文、各仕事を開けます。 |
| 次回の定期実行を調整する | 「手順を探す」→予定の「次回分を確認」で、日時を変更し、今回使わない仕事のチェックを外します。「今回は休む」でその枠だけを休止します。資料候補は指定日時と対象期間に基づき、実行時点で確定します。 |
| 一段落だけ修正する | 成果物の「修正範囲」で段落を選び、修正内容を依頼します。他の行は元版からそのまま保存します。表示する版を切り替えると修正前後と出典を比較でき、「この版を採用」で確定します。 |
| 報告に前回からの変化を載せる | 週報・月報の「前回の報告と比較」で参照する前回の版を確認します。同じ定期実行の過去の報告があれば先頭に表示します。比較結果は元の報告の該当版にも表示され、前回と今回の出典からそれぞれの元版を開けます。 |

## 工程5　完了した依頼から手順を共有する

1. 佐藤の完了した依頼で **手順の草案を作る** を選び、メモに契約条件と先方希望のどちらを先に載せるかを指定します。個人の草案を保存すると本文を確認できます。
2. **管理者に公開を申請する** を選びます。[管理画面の「手順の公開」](http://127.0.0.1:18733/admin.html#procedures) で、管理者が公開先・版・本文を確認し、**確認した手順を公開する** を選びます。
3. [田中の「手順を探す」](http://127.0.0.1:18732/#catalog) から公開された手順とB社を選びます。田中の Hermes がB社の資料を照合し、田中の回答を受け取ってメモを作成します。

共有対象は、実行に使った更新商談手順から作る手順本文、メモの構成、営業企画部の公開情報です。元の依頼との対応は Hub 内に保存します。再利用の各段階で、サーバーが所属と公開版のハッシュを確認し、本人の資料を取得します。公開版は SQLite に保存し、確認済みの本文を社員コンテナの Runs API に渡します。

[工程5の検証記録](../evidence/stage5-procedure-sharing.md) に、2モデルの結果と案件分離の照合内容を記録しています。Chrome と Playwright が利用できる環境で `node test/browser/employee/procedure-browser.mjs` を実行すると、起動済みの比較環境で完了・申請・公開・再利用を再現できます。`--local` で通常環境を使用します。実行ごとに2件の合成依頼と1件の公開手順が残ります。

### 公開手順の改訂と取消

[管理画面の「手順の公開」](http://127.0.0.1:18733/admin.html#procedures) で **手順を改訂** を選ぶと、メモの並び順をもう一方に変更する改訂案が開きます。現行版と新版の名称・版番号、新しい本文を確認して **新版を公開する** を選びます。新規依頼は受付時の最新版を使います。受付済みの依頼は手順IDと本文ハッシュから当時の版を読み、メモまで同じ版で処理します。

**公開を取り消す → 公開取消を確定する** は、その手順の全版に適用されます。社員の一覧から消え、APIで新規利用や再開を要求しても拒否されます。確認待ちの依頼には回答を保存できますが、メモ作成を起動せず、依頼詳細に停止状態を表示します。取消前に完了したメモは引き続き開けます。取消前に送信を開始した処理は先方で完了する場合があります。
